# 校准协议与档案

一张没校准过的盘，准确率大概在六到七成；校准过的能推到八成以上。
差别不在技法，在**你有没有拿真实发生的事去修正取象偏差**。

市面上的工具问完校准问题就丢了，下次重来。mingtu 存档。

## 二、校准流程

1. 首次出报告时，末尾给 3–5 条**可证伪**的过往推断（写法见 `narrative-style.md` 第七节）。
2. 命主回答后，逐条判 `命中 / 部分 / 落空`。
3. 落空的条目要归因，不要含糊记一句"不准"：
   - **取象偏差**：维度对了但性质说反了（说吉实凶）→ 检查该十神的极性判定，很可能用神取错
   - **时间偏差**：事情发生了但差一两年 → 检查起运时间与真太阳时
   - **维度偏差**：年份对了但领域错了 → 调整该盘的维度权重
   - **整体偏差**：多条集中落空 → 回头质疑旺衰与用神，甚至质疑时辰
4. 把结论写进 `adjustments`，下次读盘先加载档案。

## 三、什么情况下要推翻重来

不要因为一两条不准就改盘，也不要因为盘是算出来的就死不认错。判据：

| 现象 | 处理 |
|---|---|
| 单条落空 | 记录，不动结构 |
| 同一维度连续三条落空 | 下调该维度权重，记入 `adjustments` |
| 时间系统性偏移一到两年 | 检查起运岁数、真太阳时、是否节气交界日出生 |
| 吉凶方向整体相反 | **重查用神**。身强身弱判反是最常见的根因，从格误判次之 |
| 事件领域完全对不上 | **重查时辰**。跑 `dingshichen.py` 用已知事件反推 |

第四第五行是真正的翻车点。发生时要明确告诉命主"前一版结论的基础判断可能错了"，
不要在新报告里悄悄改口。

## 四、反推时辰的事件怎么选

`dingshichen.py` 的输入质量决定输出质量。选事件的标准：

- **时间要准到年**，模糊到"大概二十岁出头"没用
- **要有明确领域**：升学、婚姻、生育、手术、失业、创业、置产、移居
- **好坏要分明**，`valence` 填 1 或 −1；中性事件（0）几乎不提供区分度
- **至少 3 条，5 条以上才有意义**，且尽量分散在不同年份和不同领域
- 优先选**被动发生**的事（裁员、疾病、家庭变故），主动选择的事（辞职、结婚）
  掺杂个人意志，区分度较低

看 `verdict` 字段决定后续，规则见 `lifeline-rules.md` 第五节。
判定为"不可用"时不要挑第一名硬上——那等于把一个未知量伪装成已知量，
后面所有结论都建立在它上面。
