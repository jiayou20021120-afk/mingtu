# 命途

市面上的命理工具给的是**快照**：本命盘 + 当前大运 + 未来一两年。
这套给的是**形状**：出生到九十岁的完整曲线，两套体系各推一遍，逐年对账，
哪里一致、哪里打架、哪里是转折，全部标出来。

---

## 铁律（不可绕过）

1. **绝不自己排盘。** 四柱、大运起运时间、紫微十二宫、四化飞星，一律走 `mingtu` 命令。
   纯 LLM 排盘会错排日柱，日柱错则日主错、格局错、用神错，后面九十年全是反的。
   想"凭记忆快速估一下"的念头出现时，那就是必须跑命令的信号。
2. **时辰不能猜。** 不知道就走 `mingtu hour` 反推；反推不出来就按未知处理并明说哪些结论看不了。
   默认填子时是错误做法。
3. **分歧不许和稀泥。** 八字与紫微给出相反信号的年份，如实说两套读法相反，不挑好听的写。
4. **不算生死。** 不推寿元，不谈大限之年。被问到直说不做。
5. **每条断语标来源。** A 历法计算 / B 规则判定 / C 典籍演绎 / D 自由推测。D 级原则上不写。
6. **相对表述，不用绝对分。** 说"这是你十步大运里最好的一步"，不说"这步 0.74 分"。
   绝对分在人与人之间不可比。
7. **免责声明每次必带。**

## 环境

检查是否已装：

```bash
mingtu --version
```

没装就装（只需一次）：

```bash
pip install mingtu
```

装好之后**不要主动跑自检或示例盘**，等用户给生辰再开工。

## 收集信息

必需：出生日期（公历优先；农历要问清是否闰月）、出生时间、性别。
强烈建议：出生城市（真太阳时校正。东西部差异可超过两个时辰）。

用自然语言问，一次问完，不要做成表单逐项审问。
用户说"不知道几点"就直接进反推流程，不要反复追问。

## 工作流

### 一步到位

用户第一次来，直接跑完整管线：

```bash
mingtu full --solar 1995-3-12 --time 14:20 --gender 女 --city 杭州 \
            --name 张三 --outdir ./mingtu-out --today
```

产出 `chart.json`、`lifeline.json`、`张三-命途.html`，并打印十步大运摘要与今日运势。
stdout 的摘要就是你写报告的骨架。

### 用户想自己点，不想看命令行

```bash
mingtu serve
```

起本地网页表单并自动开浏览器，只绑 127.0.0.1。
用户说"能不能有个界面""我自己填""想给我妈算"这类话时，直接给这条命令，
比让他背参数强。表单里含时辰反推入口。

### 分步

```bash
mingtu chart  --solar 1995-3-12 --time 14:20 --gender 女 --city 杭州 --out chart.json
mingtu life   --chart chart.json --to-age 90 --out lifeline.json
mingtu day    --chart chart.json --date 2026-08-09 --span 7
mingtu render --chart chart.json --lifeline lifeline.json --out 命途.html
```

其他参数：`--lunar` 走农历；`--lon` 直接给经度；`--no-tst` 关闭真太阳时校正；
`--hour-unknown` 标记时辰不确定；`--sect 1|2` 子时口径。

### 两类必须处理的警告

**⚠ 真太阳时使时辰跳变** —— 两个时辰的盘都要排，报告里说明。

**⚠ 生于晚子时**（23:00–24:00）—— 早子时法与晚子时法**给出不同的日主**，
不是细节差异，是全盘换人。默认走晚子时法（`--sect 2`）。必须向命主说明用了哪个口径，
并把另一派的四柱一并给出（在 `meta.sect_alternative` 字段里）。
命主若已有其他软件或老师排的盘，**沿用他那边的口径**，不要制造第二套说法。

## 写报告

按 `narrative-style.md` 第六节的七段结构。三处不许省：

- **第二节"形状"**是全篇题眼，写在最前面：一句话说清这辈子的曲线走势
  （早发 / 晚成 / 中间高两头低 / 一路缓升 / 双峰）。
- **第六节"分歧与限度"**：两套体系全生命周期通常只有两三成年份强一致，
  把这个事实和具体的分歧年份都写出来。
- **第七节"校准问答"**：3–5 条可证伪的过往推断。

## 日常运势

用户只想看今年或今天，不要跑全套九十年报告：

```bash
mingtu day --chart chart.json --span 7
```

输出流年、流月、流日三层各自的六维分与叠加结果。
权重是 年 1.0 / 月 0.55 / 日 0.3——**一天不决定什么**，
所以不要把一个好流日说成行动信号。`stacked.dominated_by` 告诉你这次到底是哪一层在说话。

日常运势同样守反巴纳姆纪律。"今天宜静不宜动"这种话不要写。

## 时辰未知

```bash
mingtu hour --solar 1995-3-12 --gender 女 --city 杭州 \
  --events '[{"year":2013,"desc":"考上大学","valence":1},
             {"year":2019,"desc":"住院手术","valence":-1},
             {"year":2021,"desc":"结婚","valence":1},
             {"year":2023,"desc":"裁员","valence":-1}]'
```

十二个时辰各排一套盘，拿已知事件打分排名。看 `verdict`：

- **可用** → 按第一名走，全文标注"时辰为反推所得"
- **待定** → 前两名并行呈现，只讲两盘都同意的部分
- **不可用** → 按时辰未知处理：只做年月日三柱，不谈子女宫、不谈晚运、不谈紫微十二宫，
  明说这些看不了。**不要挑第一名假装知道。**

事件怎么选见 `calibration.md` 第四节。少于三个会警告，五个以上才有区分度。

## 校准档案

报告末尾的校准问答，命主回答后要记下来，别丢：

```bash
mingtu profile save --slug zhang-san --name 张三 \
  --solar 1995-3-12 --time 14:20 --gender 女 --city 杭州 \
  --chart chart.json --lifeline lifeline.json

mingtu profile calibrate --slug zhang-san --year 2019 --dim 健康 \
  --predicted "健康维度触底且冲日支" --actual "住院手术" --verdict 命中

mingtu profile list
mingtu profile show --slug zhang-san
```

档案存在 `~/.mingtu/profiles/`（可用 `MINGTU_HOME` 改）。
它会自己算命中率、按维度归因，并在某个维度连续落空三次时提出调整建议。
**同一个人再来，先 `profile show` 读档案，不要从头再问一遍。**

## 常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| `mingtu: command not found` | 没装 | `pip install mingtu` |
| 用户想要图形界面 | — | `mingtu serve` 起本地网页表单 |
| 六个维度里某一个永远最高 | 正常。用神对应的那个维度就是会高 | 用 `rank` / `percentile_in_life` 做相对表述 |
| 关键转折点一个都没有 | 该盘结构平稳 | 如实说"你这辈子没有剧烈的结构性转折"，这是有效信息 |
| 两套体系大面积分歧 | 正常，通常只有两三成年份强一致 | 写进"分歧与限度"，不要藏 |
| 四柱与命主手上的盘对不上 | 多半是口径差异 | 查 `lifeline-rules.md` 第六节口径表，别急着说对方错 |
| 用户问"我能活到几岁" | — | 直说这一项不做，转向可谈的部分 |
| 用户拿结果做重大决策 | — | 给结构信号，不给指令，明确说决定权在他 |
